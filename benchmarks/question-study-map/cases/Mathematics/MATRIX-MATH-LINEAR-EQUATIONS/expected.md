# Expected behavior — One-unknown linear equations over the rationals

Baseline: `e6f9ccce4a2ecbba8764bfa5cd5e877830afa56d`

The expectations below are derived from the benchmark contract and the frozen canonical model. They are written independently of any repair proposal.

| Case | Expected |
| --- | --- |
| Direct-ready question | A representative question demand should resolve to one clear primary capability and a usable canonical teaching destination. |
| Prerequisite route | Prerequisite order should follow capability prerequisite_refs, including cross-matrix dependencies, never cross-matrix rung-number comparison. |
| Multi-capability question | Primary ownership must remain distinct from meaningful secondary capabilities; transitive prerequisites must not be copied into secondary demand. |
| Repeated demand | Multiple questions reusing one capability should consolidate teaching rather than duplicate it. |
| Unknown learner | No learner estimate/evidence must not create invented mastery; the route should remain conservative. |
| Rough owner estimate | A rough percentage may select a starting coordinate but must never create DEMONSTRATED evidence. |
| Prior learner evidence | Direct/diagnostic evidence should override a rough owner estimate when both exist. |
| External provider bridge | Declared external-provider prerequisites must stay visible as bridges and must not become fake local teaching or fake mastery. |
| Content gap | A missing canonical teaching location must remain explicit; the system must not fabricate a microtopic or mark the matrix ready. |
| Incomplete source | A question requiring missing figure/table/source information must remain unresolved rather than guessed. |
| Feedback diagnosis | For a represented capability, a wrong attempt may identify the first supported failure using canonical misconception/diagnostic evidence; ambiguous failure must not be guessed. |
| Repair | Repair should target the failed capability/misconception and use existing teaching/reconstruction content rather than restart an unrelated topic. |
| Fresh verification | After repair, verification should use a fresh same-capability question or exit task rather than the already-solved external question. |
| Help-dependent success | Correct work after help must remain non-independent evidence and must not be promoted to DEMONSTRATED. |
| Independent success | Independent correct verification may draft DEMONSTRATED evidence and a later review date; persistence remains explicit. |

## Forbidden outcomes

- Do not invent a missing capability, microtopic, figure, learner state or source fact.
- Do not use cross-matrix ladder positions as global ordering.
- Do not convert a rough owner estimate into mastery evidence.
- Do not turn an external provider bridge into local teaching.
- Do not canonicalize a benchmark question merely to make the case pass.
- Do not repair production content/runtime from this benchmark pack.
